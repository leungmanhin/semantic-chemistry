# `petta/` — the Mortal Semantic Chemistry stack ported to PeTTa (TECAN backend migration)

The Python engine in `../src/` is the reference + **replay oracle**; this directory is the **PeTTa backend** the IR migrates to (kept log-equivalent, not rewritten — schema §4–5, eq 30). Per [[design-decisions]] D3 the rule-lift was done *directly in PeTTa* (PeTTa rules ARE data, so porting = lifting). **Ported so far: P0 kernel + P1 evaluator + P3 evolve; P4 worker ecology IN PROGRESS (P4.1 §6.4 contract + dispatcher; P4.2 separate-space isolation + reducer; **P4.3 worker kinds — ecan-epoch, acs-scan+replay, selection-epoch; P4.4 backend-rendering test + evaluator_defs factoring — all DONE**). **The full P0–P4 Mortal Semantic Chemistry stack is ported to PeTTa, log/result-equivalent to the Python oracle — 86 tests green, plus an automated whole-run equivalence capstone (`src/equivalence.py`).** Remaining: the "later" stage = MeTTa-IL backend migration (a backend swap under log-equivalence, not an architectural rewrite).** Per [[design-decisions]] **D5** the remaining multi-run orchestration (the P1 epoch loop, P2 `acs_detect` ablation+SCC, P3 selection loop) is a *different layer* that lands **at P4 as worker kinds**, not a bespoke MeTTa detour — so it is built here, not back-filled into the per-run modules.

## Why `&self` (not `&mork`)

`&mork`'s `match` (current MORK FFI) **cannot join**: a nested `&mork` match cross-products (the inner ignores the outer-bound var) and compound result-templates lose bindings. So derivation runs in `&self`, where nested `match` joins correctly; the experiment's data (pure facts under `../experiments/<expt>/`) is loaded into `&self` via its `load.metta`. MORK-accelerated conjunctive matching needs a `query-multi` FFI primitive (deferred). See [[petta-findings]] for this and the other idioms (`case`-over-`collapse` = fire-once dedup + negation; `&self` doesn't dedup; a failing `!(test)` aborts the file).

**Refinement (P4.2, `spaces_behavior.metta`):** the no-join limitation is specific to the `&mork` FFI — *native* fresh `(new-space)`s join under nested match exactly like `&self`, and even join *across* spaces. That cross-space join is what lets the worker ecology keep the read-only IR shared in `&self` while each worker holds its mutable state in its own space.
