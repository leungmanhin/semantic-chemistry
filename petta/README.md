# `petta/` — the Mortal Semantic Chemistry engine (PeTTa backend)

The reusable, **facts-free logic** of the Mortal Semantic Chemistry stack on the PeTTa backend, in the **canonical per-match form**. The reference for correctness is **Ben's `docs/` PDFs**.

The clean cut across the repo:
- **`petta/` = logic** — the engine (`util`/`fuel`/`compiler`/`gate`/`reaction`), the solve layer (`grounder`/`evaluator`), the metabolic-closure `epoch` loop, the `acs` detector, and the worker layer (`worker` envelope + `chamber`/`ecan`/`reducer` bodies + `dispatch`), imported by the suite (this directory).
- **`../tests/` = the suite** — each file demonstrates + verifies a slice of the stack with its own `!(test …)` assertions (run with `sh tests/run_suite.sh`; 391 tests green).
- **`../experiments/<expt>/` = facts** — molecules · tasks · configs · the genome `rules.metta`.

A rule's **source of truth** is the backend-neutral **canonical IR** in `../experiments/expt1-causal-qa/rules.metta` — separate `rule-lhs`/`rule-rhs` facts with `(var Name)` markers, in pure per-match `C ^ G1 ==> G2` form (MSC §2.1, §4.3 eq 12–16: one firing per match θ, `X' = X ⊕ θ(G2)` set-union). The engine converts this to a runnable form at genome-expression time and runs the rules in `rule-priority` order, fuel-gating each firing.

The execution model is **TECAN Alg 5.1 collect-then-fire**: `rules-pass` assembles the candidate queue in full (line 10) before the first rewrite (line 16), so every precondition is evaluated against the **epoch-start state**, nothing in the queue was enabled by anything else in it, and a chain advances **one hop per cycle**. One pass is therefore **one epoch, not a finished derivation** — the task loop (`epoch.metta`) runs cycles until the chamber settles, and `settle-from` is the bare equivalent for a genome run with no task posed. Queue order is `rule-priority` as a **placeholder**: Alg 5.1 pops best-first keyed by `TECANScore`, which allocates a scarce budget across affordable acts, where priority is a topological sort — deterministic, and immaterial while fuel covers every candidate.

One that cannot pay — or whose genome declares no cost at all — has no soma and none of its rules run (MSC eq 20 `cexpr`; a death mode prior to starvation-by-firing). Expression is never free by omission, so a forgotten declaration surfaces as an organism that does not run rather than one that runs unpriced. |

The per-firing gate (MSC eq 24 / §3 step 3): `gate?` = `afford?` ∧ `in-attn?` (`in-attn?` over `(attention R tok v)`); `all-sorted-rules` is the raw, unfiltered priority order. Reduce to `afford?` on Exp-1 (attention vacuous, single chamber). |
| `reaction.metta` | the firing **ENGINE** (`$ws`-parameterized, re-run-safe): set-semantics `add-all` (the doc's ⊕) · `fire` + cycle-tagged event log (`current-cycle` tags each firing; `log-facts` reads the ordered log back) · `collect-rules`/`fire-queue` (TECAN Alg 5.1, queue entries `(qcand RULE ORG KEY COST PRODS)`) sharing the `admissible?` guard (not already fired this cycle ∧ products not all present ∧ gate open), which Alg 5.1 evaluates at collection *and* again at firing since an earlier entry may since have supplied the products or spent the fuel; an entry whose re-check fails is **dropped** and the queue continues, because the queue is mixed-rule and a later entry may be independent of what the earlier one exhausted · **`rules-pass`**, the one-epoch step every entry point goes through · the generic **`run-rules`** (raw, all rules) / **`run-chamber`**+`run-chamber-from` (only chamber `$ch`'s admitted rules) / **`run-chamber-b`** (budgeted, MSC §6.4 `worker-budget-steps`; the doc's epoch bound `B`) / **`run-ablate`** / **`run-chamber-ablate`** (the ACS condition-4 counterfactual) · and the run-to-**settle** family (`settle-from`/`run-rules-settle`/`run-chamber-settle`), which iterates epochs until one fires nothing — the bare assay for a genome run with no task posed, where the task loop is the form with the metabolic bookkeeping. Every stage runs its genome through this. NO domain logic, NO data. |
| `grounder.metta` | the skeleton **GROUNDER** — `ground-skeleton $ws $gas` grounds an `answer-skeleton` against the molecules **in run space `$ws`** (`&self` or a worker's isolated space; §10.1 IR): the query-solving step, a MeTTa-match stand-in for a PLN backward-chainer query. The skeleton STRUCTURE is read from `&self` (read-only IR); the join hits `$ws`. Conjunct `sem-edge`s become joinable clauses (`(var …)` markers co-refer by name; joined via the compiler's `clause-join`; the graph pinned by `sem-graph-kind`). A solution = the grounded conjunct list — each element a **cited molecule sem-edge**, provenance built in. The **answer count** `total-answers $ws` (via `question-answers`/`skeleton-answers`) sums the groundings over every question — the system's output, read by the epoch loop (per-cycle fitness proxy) and the ACS replay-ablation (baseline / ablated count). |
| `evaluator.metta` | the **EVALUATOR** (MSC §4.4: the sole minting authority — the soma never mints) — scores each **grounding** (Match is binary per solution; every solution mints, per-solution piece-rate) and converts its **achievements** into **typed fuel** under a clamp's `(clamp-mint CL achievement tok n)` facts: `skeleton-match` (every grounding) · `transitive-explanation` (chain-derived citation, depth ≥ 2 read **structurally** from the provenance ids — the IR convention: a derived id = step-name + premise-ids; no genome vocabulary named). Credited (`fuel.metta`'s `credit`) to the organism whose rule **derived the cited edge** — the producer looked up in the event log (`producer-of` → `rule-organism`). Income accessors (per token): `solution-mint` / `skeleton-income` / `question-income` / `chamber-income`; crediting: `credit-question` (`credit-all-questions` over the whole task set). Also carries `run-eval`, the **evaluator** worker body (worker-kind `evaluator`): mint every question in a worker's already-derived space under its clamp + emit the purses (the token delta) — the minting stage a context-chamber worker omits, run on the same space via a sequential handoff. |
| `epoch.metta` | the **TASK loop** (hot-pool management — `refresh-pool`/`open-task` — lives in `worker.metta`, since the pool is the worker's material and `worker` loads first) (a reduced TECAN epoch, Alg 5.1 — its rent/shadow-prices/scored-gate unbuilt). A **task** is one arriving corpus item, a text and the questions asked of it. `run-task` poses it, hands the chamber a **fresh hot pool** holding just that task's text (`open-task` → `refresh-pool` + `copy-molecules`), works it (`work-task`), then mints + credits under the clamp — pose · work · credit is the trio, and the credit step is either this one or the evaluator worker, never both. `run-tasks` runs a stream of them, numbering cycles so no two tasks share one; a production harness receives arrivals from outside and calls the trio per arrival instead. **`work-task` runs cycles until the chamber SETTLES** — a whole cycle fires nothing more — or the cycle allowance or the total firing budget `$b` runs out (`budget-left` carries `worker-budget-steps` across the whole task rather than per cycle, so a bounded worker stops where it always did). It is what a context-chamber worker runs on. Halting on settled rather than on "an answer appeared" is deliberate: a control loop does its consolidating *after* the answer, so stopping at the first grounding would cut the loop off mid-turn. A derivation needs as many cycles as its chain is deep, which is why this is a loop; how many belongs to the task, not to the engine. `work-task-ablate` is its ablating twin, and has to stay a twin — a counterfactual is only paired with its real run if both are given the same chance to settle. **What survives a task boundary is what MSC eq 8 puts inside the organism, `O = (@R, X, F, C, L)`**: the purse `F` and the event log `L` ride with the soma, while the hot pool `X` turns over. So an organism carries its metabolic position across arrivals — alive while income ≥ spend, thriving at surplus > 0 (MSC eq 19, an expectation over *repeated* operation) — but carries no working material. Within a task products **persist** across cycles (a chain needs its intermediates alive when the cycle that consumes them runs) and a rule whose products are already present does not re-fire, so a settled task stops spending. Each cycle **`set-cycle`** tags `(cycle-now k)` — so `fire`/`fired?` scope to that cycle — and dates it to the task it served (`(cycle-task k t)`), which is what lets the detector count turns per task. Runs in `&self` **or a worker's space**. Re-hosted on the `ecan-epoch` worker — see `ecan.metta`. |
| `acs.metta` | the **ACS detector** (TECAN T3 / Alg 5.5 step 2 / MSC eq 18–19) — mine the reaction graph from the event log + rule IR, discover the food-generated reflexively-autocatalytic loop **A = (M_A, R_A)**, certify its §4.5 conditions, emit the §2.9 verdicts. Graph is keyed on the **MOTIF** — a rule's whole reactant/product PATTERN (a list of sem-edge clauses, jointly canonicalized so shared vars are kept — `rule-reactant`/`rule-product`/`canon-motif`), so a multi-edge premise like a causal chain is ONE composite motif; product-feeds-reactant is decided by **UNIFICATION** (`unify`/`motif-feeds?`, a common instance — handling subsumption, nested args, and a single edge feeding a multi-edge premise). **Structural closure** (§4.5 cond 1, `structurally-closed?`/`closure-kind`) is computed over the **endogenous** feeds ONLY — a member must both lie on a member-to-member feeds cycle (`rule-feeds-rule?`/`endo-cyclic?`) **and** have its whole non-food premise **injectively** regenerated by member products (`injective-covered?`: each non-food premise clause matched to a *distinct* member product; a clause no member produces is food and exempt). The injective half is what stops a *contracting* self-loop — two premise clauses of a relation, one product of it — from passing as a closed singleton, while a balanced singleton that regenerates its own catalyst still does. The evaluator's minting edge is **FOOD** (external reward), not closure. **Subset-mining**: `endo-component` peels the fired set to a fixpoint (dropping a feed-forward converter can un-cover a member that leaned on it), and `acs-member-set` takes that closed component when non-empty, else falls back to the food-fed candidate network (`acs-members`) so a not-closed candidate is still reported. The `acs-closure` fact is emitted **only when closed** (`closure-facts`), and `closure-kind` classifies it from the relations the loop **regenerates** (`closure-rels`, its members' non-food premise relations) against `(control-relation R)` declarations: `substrate` (all semantic) / `control` (all internally-generated control motifs) / `hybrid` (mixed). A **food-fed / subsidized candidate is NOT an ACS**, so it emits **no** `acs-closure` — its state is read off as surplus-but-no-closure (`closure-of` returns `none`). The food set is the cue motifs **and** the reward. Membership + closure are clamp-**independent**; the **clamp-switch shows in the componentwise `acs-surplus`** (`token-surplus`, eq 19) — a costed token whose income < spend fails condition 3 under that clamp (the same loop is viable under one clamp, starves under another). **Condition 4 (causal influence)** is a REPLAY ablation — `causal-influence?`/`ablated-answers` re-pose the task in a caller-bound **isolated** space and work it to settle with the members suppressed (`work-task-ablate`); if the answer count drops below the `total-answers` baseline, the loop causally produces the answers — computed ONCE as `$ci` and emitted as `acs-causal-influence`. **Per-rule causal coding** (SC §3) breaks that down per member: `member-do-influences` runs a **leave-one-out** replay per member and emits `rule-do-influence R target answer-reward tasks n` + `rule-redundancy R tasks bool`. The replay re-poses whole **tasks** (`windowed-reward` → `ablate-tasks` → `ablate-task`: pose it into a fresh pool → **work it to settle** with the rule suppressed → read the minted reward → **credit** it), measured against an unablated run of the same length in a `wipe-space`d replay space. Working to settle rather than running one cycle is what keeps the two sides paired: under collect-then-fire a chain takes several cycles, and a replay cut short never reaches the part of the derivation the baseline was measured over, so every member's contribution collapses toward zero. `replay-cycles` (config `(acs-replay-cycles n)`, default 20) bounds a replay that never settles — a runaway guard, not a tuning dial. The crediting step is load-bearing too: without income the organism cannot afford the second task, so ablated and unablated runs alike collapse to the first and every difference vanishes. The window is `window-of` = the task sequence the observed log served, **capped by `(acs-window-max n)`** (config, default 3; `window-max`) — pairing with the certified run on a short log, bounded on a long one, since past the task where the trajectories separate each further one only adds a constant — and it is recorded in the fact, because a strategy that primes itself for the *next* arrival reads 0 over one task while being load-bearing over two. `minimal-acs` uses the same window and finds a working minimal set by **greedy sequential** ablation (`greedy-minimize` carries an accumulated skip set, so a *mutually* redundant group — each member droppable alone, not all together — keeps one survivor instead of collapsing to the empty set); it is *a* minimal set, not *the* minimum one. On a one-task window it would drop every self-priming loop's control rules and return a set that no longer closes, so the window is what makes it sound. `acs-verdicts` emits both **M_A** (`acs-motif` per motif species — `acs-motifs`, the cycle's motif patterns incl. the composite chain `((ReasonFor (mvar 0)(mvar 1)) (ReasonFor (mvar 1)(mvar 2)))`; food motifs excluded) and **R_A** (`acs-member`), plus `acs-closure` + `acs-autocatalytic` (structural, §4.5 cond 1–2), `acs-surplus` (cond 3), `acs-causal-influence` (cond 4) + `acs-recurrent` (recurrence counted across the TASKS the log served — one arrival = candidate); heritability (cond 5) is P3. Each condition is its OWN fact — there is **no `acs-promoted`/certified summary**; a consumer conjoins them ("certified ACS under CL" = `acs-closure` present ∧ every `acs-surplus`>0 ∧ causal ∧ recurrent). Reachability (`succs`/`preds`/`cycle-through`) is generic. Also carries `run-as`, the **acs-scan** worker body (the certification hosted as a §6.4 worker kind in isolated spaces). |
| `ctrl_scaffold.metta` | **CTRL-SCAFFOLD** — deriving a control level around a rule chain the log says keeps working. Detection is NOT done here: scaffolding is a second CONSUMER of the ACS scan, not a second scan. `acs-chain` (the members the scanner recorded) · `verdict-recurrent?` / `verdict-closed?` · **`scaffoldable?`** = recurs ∧ not closed — the trigger read off the scanner's own per-condition verdicts, in keeping with there being no single "promoted" summary fact. Plus `chain-answering-members` — the chain's DELIVERING end, computed from dataflow (a member whose own premise the chain feeds, producing what a query asks for) rather than read off an ordering, since the members are a connected set and the one ordering that exists (`rule-priority`) is the hack being removed. Then the **GENERATOR** `scaffold-facts`: a PURE function returning the wrapper's whole fact list — gated copies of each member (activation premise prepended, RHS untouched so product ids and achievement typing are unaffected) · `recall` (an arriving cue activates the strategy) · `worked` (premised on the delivering member's own RHS pattern, provenance id included, so a one-hop cannot claim a chain's success) · `learn` · `prime` (the closing edge) · the offspring organism with its own genome and dequote price · the control vocabulary it introduces. Purity is structural: `add-atom` does not evaluate, so a pre-built list plus one `add-all` is the only safe way to write facts with constructed compound ids. Fails closed on an undeclared cost or nothing delivered. Then **REPRODUCTION + the `ctrl-scaffold` WORKER** (`run-cs`, dispatched): the chain's members belong to different organisms, so the wrapper is their recombinant OFFSPRING (§4.5 "copied, mutated, RECOMBINED") and eq 20's `crep` falls on the parents — `chain-parents` · `contribution` · `parent-due` · `parents-can-pay?` · `charge-parents`. Costs are declared PER CONTRIBUTED MEMBER, so the split is exactly proportional with no fractional tokens, and the endowment moves from the parents' purses into the offspring's. All-or-nothing: **a parent too poor to endow cannot reproduce**, and a solvent co-parent is not charged for a wrapper that never gets built. Names no relation, question type or corpus item — the routing cue is `(task-cue-relation R)` data. |
| `worker.metta` | the shared worker **ENVELOPE** (MSC §6.4) — the worker-generic infrastructure every kind reuses (a *worker* is the general unit; context-chamber/reducer/… are *kinds*): `copy-molecules` (materialize the parser's **surface** molecules — never derived products, `mol-surface?` — into a worker's **isolated** hot-pool space, never `&self`, *"no shared-hot-pool mutation"*, so the worker re-derives from scratch), `restore-snapshot` (fuel from a declarative `(snapshot-fuel …)`), `worker-budget` (the deterministic `worker-budget-steps`), and `emit-summary` (firings + one `(worker-purse W O tok n)` per surviving purse → `&self`). The read-only IR stays in `&self`; only the compiled crules land there. |
| `chamber.metta` | the **context-chamber** worker body (`worker-kind context-chamber`) — `run-cc`: own space → `open-hot-pool` (pose the worker's task, materialize its text) → `restore-snapshot` → **`work-task`** (cycles until the chamber settles, bounded by `worker-cycles` and `worker-budget-steps`) → `emit-summary`. The worker is the doc's §6.4 unit of chamber computation; **working a task is the loop underneath it**, and there is exactly one such loop — the detector's paired counterfactual runs its twin, and a run whose cycles are dated to a task is what lets the replay re-pose that task instead of falling back to the whole corpus. The derivation + the **cycle-tagged event log** live in the worker's space — the space-parameterized pipeline running off `&self` (via the `$ws`-threaded grounder + `clause-join`). Deriving only; minting (the ecan-epoch kind) is a separate body. |
| `ecan.metta` | the **ecan-epoch** worker body (`worker-kind ecan-epoch`) — the **minting** kind (vs context-chamber's deriving-only). `run-ee`: own space → restore snapshot fuel → work ONE arriving task (`epoch.metta`'s `run-task`) until the chamber settles or its `worker-cycles` allowance runs out, minting + crediting under `worker-clamp`, in isolation → emit the answer trajectory + total firings + final purse. The purse persists in the space; the single cycle-tagged event log accumulates in place. A worker is handed one task — a stream of them is the harness's business, not the worker's. |
| `reducer.metta` | the **reducer** worker body (`worker-kind reducer`) — `run-reduce`: a **synchronization boundary** (MSC §6.4) that merges the per-worker summaries across a `par-group` into `(reduced total-firings PG n)` in `&self`. **Re-run-safe** — the reduced fact is replaced, not stacked (`clear-reduced`; the value is `let*`-bound before `remove-atom`). |
| `dispatch.metta` | the §6.4 worker **DISPATCHER** — `dispatch`: a `case` on `worker-kind` routing a worker to its body (`context-chamber`→`run-cc`, `ecan-epoch`→`run-ee`, `reducer`→`run-reduce`, `acs-scan`→`run-as`, `evaluator`→`run-eval`; an unknown kind hits the `$other` fallback). The switchboard only; the bodies live in their body modules. |

None of these logic modules carry data or a test of their own — each is a facts-free def collection that assumes the engine/evaluator is loaded by the consumer, and is exercised by the matching `*_test.metta` in `../tests/`. The end-to-end pipeline demo lives in `../experiments/expt1-causal-qa/demo.metta`.

## Why `&self` (not `&mork`)

`&mork`'s `match` (current MORK FFI) **cannot join**: a nested `&mork` match cross-products (the inner ignores the outer-bound var) and compound result-templates lose bindings. So derivation runs in `&self` (where nested `match` joins correctly), with each worker's mutable state in its own native `(new-space)`. MORK-accelerated conjunctive matching needs a `query-multi` FFI primitive (deferred). Other PeTTa idioms in play: `case`-over-`collapse` = fire-once dedup + negation; runtime var-minting in the converter; `&self` doesn't dedup so the engine uses set-semantics add; a failing `!(test)` aborts the file.

**Refinement (`../tests/spaces_behavior_test.metta`):** the no-join limitation is specific to the `&mork` FFI — *native* fresh `(new-space)`s join under nested match exactly like `&self`, and even join *across* spaces. That cross-space join is what lets the worker ecology keep the read-only IR shared in `&self` while each worker holds its mutable state in its own space.
