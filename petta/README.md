# `petta/` — the Mortal Semantic Chemistry engine (PeTTa backend)

The reusable, **facts-free logic** of the Mortal Semantic Chemistry stack on the PeTTa backend, in the **canonical per-match form**. The reference for correctness is **Ben's `docs/` PDFs**.

The clean cut across the repo:
- **`petta/` = logic** — the engine (`util`/`fuel`/`compiler`/`gate`/`reaction`), the solve layer (`grounder`/`evaluator`), the metabolic-closure `epoch` loop, the `acs` detector, and the worker layer (`worker` envelope + `chamber`/`ecan`/`reducer` bodies + `dispatch`), imported by the suite (this directory).
- **`../tests/` = the suite** — each file demonstrates + verifies a slice of the stack with its own `!(test …)` assertions (run with `sh tests/run_suite.sh`; 236 tests green).
- **`../experiments/<expt>/` = facts** — molecules · tasks · configs · the genome `rules.metta`.

A rule's **source of truth** is the backend-neutral **canonical IR** in `../experiments/expt1-causal-qa/rules.metta` — separate `rule-lhs`/`rule-rhs` facts with `(var Name)` markers, in pure per-match `C ^ G1 ==> G2` form (MSC §2.1, §4.3 eq 12–16: one firing per match θ, `X' = X ⊕ θ(G2)` set-union). The engine converts this to a runnable form at genome-expression time and walks the rules in `rule-priority` order, fuel-gating each firing.

## Files

| File | What |
|------|------|
| `util.metta` | generic **list/term helpers** (no domain, no facts): `filter-out` · `concat-lists` · `in-list?` · `dedup` · `map-snd` · `all-at-least?` · `len` · `remove-one` · `remove-all` (drop already-ground atoms from a space) · `derived-id?` (a compound edge-id marks a derived product vs an atomic parser id) · `persistent-rel?` (a relation declared `(persistent R)` — decay-exempt). Loaded first; the other modules build on these. |
| `fuel.metta` | the per-organism typed-fuel **LEDGER** + organism-purse resolution — `fuel-of`/`afford?`/`debit`/`debit-all`/`credit` on `(fuel O tok n)` (schema §2.3; `credit` creates a missing purse, so an organism can earn a token it never held), `rule-organism` (a rule → its owning organism via ruleset membership; `O_none` when unowned, so it cannot afford to fire), and the **structural-assay seeding** `seed-assay` (every organism × every `genome-tokens` cost token). The metabolic substrate the engine spends on; the growth home for the token economy. |
| `compiler.metta` | **rules-as-data**: the canonical-IR **converter** (`to-vars`/`convert-rule` — `(var Name)` → co-referent match-vars, `rule-lhs`/`rule-rhs` → a runnable `(crule …)`) + the match **enumerator** (`clause-join`/`rule-cands`). A bare clause matches the **run space `$ws`** (the hot pool — `&self` on a bare run, a worker's own space under isolation); an explicit `(at self PAT)` routes to `&self` for a read-only-IR read. Also owns **EXPRESSION** (`express`/`express-organism`/`expressed?`/`genome-cost`): compiling a rule is a shared, idempotent, free build artifact, but having a **soma** costs — an organism pays its `(genome-token-cost GNM tok n)` once per hot pool and is marked `(expressed O)`. One that cannot pay — or whose genome declares no cost at all — has no soma and none of its rules run (MSC eq 20 `cexpr`; a death mode prior to starvation-by-firing). Expression is never free by omission, so a forgotten declaration surfaces as an organism that does not run rather than one that runs unpriced. |
| `gate.metta` | **context admission** + the per-firing fire **DECISION**. Context admission (MSC §3 step 1): `chamber-rules $ch` keeps a chamber's rules by context-subsumption (`rule-eligible-in? $ch` — a rule is admitted iff its `rule-context` is one of `$ch`'s `chamber-context` facts; unconstrained rules always). The per-firing gate (MSC eq 24 / §3 step 3): `gate?` = `afford?` ∧ `in-attn?` (`in-attn?` over `(attention R tok v)`); `all-sorted-rules` is the raw, unfiltered priority order. Reduce to `afford?` on Exp-1 (attention vacuous, single chamber). |
| `reaction.metta` | the firing **ENGINE** (`$ws`-parameterized, re-run-safe): set-semantics `add-all` (the doc's ⊕) · `fire` + cycle-tagged event log (`current-cycle` tags each firing; `log-facts` reads the ordered log back) · fire-once-per-cycle `walk` (halts at the step budget `$b`; `budget-reached?`) · the generic **`run-rules`** (raw, all rules) / **`run-chamber`**+`run-chamber-from` (only chamber `$ch`'s admitted rules; `-from` re-enters mid-run) / **`run-chamber-b`** (budgeted, MSC §6.4 `worker-budget-steps`) / **`run-ablate`** (raw, skipping a set) / **`run-chamber-ablate`** (chamber-scoped, skipping a set — the ACS condition-4 counterfactual), all walking by `rule-priority`. Every stage runs its genome through this. NO domain logic, NO data. |
| `grounder.metta` | the skeleton **GROUNDER** — `ground-skeleton $ws $gas` grounds an `answer-skeleton` against the molecules **in run space `$ws`** (`&self` or a worker's isolated space; §10.1 IR): the query-solving step, a MeTTa-match stand-in for a PLN backward-chainer query. The skeleton STRUCTURE is read from `&self` (read-only IR); the join hits `$ws`. Conjunct `sem-edge`s become joinable clauses (`(var …)` markers co-refer by name; joined via the compiler's `clause-join`; the graph pinned by `sem-graph-kind`). A solution = the grounded conjunct list — each element a **cited molecule sem-edge**, provenance built in. The **answer count** `total-answers $ws` (via `question-answers`/`skeleton-answers`) sums the groundings over every question — the system's output, read by the epoch loop (per-cycle fitness proxy) and the ACS replay-ablation (baseline / ablated count). |
| `evaluator.metta` | the **EVALUATOR** (MSC §4.4: the sole minting authority — the soma never mints) — scores each **grounding** (Match is binary per solution; every solution mints, per-solution piece-rate) and converts its **achievements** into **typed fuel** under a clamp's `(clamp-mint CL achievement tok n)` facts: `skeleton-match` (every grounding) · `transitive-explanation` (chain-derived citation, depth ≥ 2 read **structurally** from the provenance ids — the IR convention: a derived id = step-name + premise-ids; no genome vocabulary named). Credited (`fuel.metta`'s `credit`) to the organism whose rule **derived the cited edge** — the producer looked up in the event log (`producer-of` → `rule-organism`). Income accessors (per token): `solution-mint` / `skeleton-income` / `question-income` / `chamber-income`; crediting: `credit-question` (`credit-all-questions` over the whole task set). Also carries `run-eval`, the **evaluator** worker body (worker-kind `evaluator`): mint every question in a worker's already-derived space under its clamp + emit the purses (the token delta) — the minting stage a context-chamber worker omits, run on the same space via a sequential handoff. |
| `epoch.metta` | the metabolic-closure **EPOCH loop** (a reduced TECAN epoch, Alg 5.1 — its rent/shadow-prices/scored-gate unbuilt) on the sem-graph pipeline — each cycle re-runs the genome: `run-chamber` (fuel-gated re-derivation) → ground + **mint+credit** the skeletons (`evaluator`) → **`decay`** the derived layer (drops compound-id edges; keeps molecules + fuel + the cycle-tagged event log, **and any relation declared `(persistent R)`** — a persistent molecule whose edge *and* TV survive the forgetting, our stand-in for importance-graded retention, so a closed loop can carry a motif across the cycle boundary) — our device to make the eq-19 accounting visible by forcing re-derivation, **not** the maintenance cost (`cmaint` = TECAN's unbuilt **rent**, which kills *idle* loops via a fuel charge; decay charges no fuel, so an idle loop doesn't starve — it just goes silent; loosely a "forgetting", TECAN §4.6). So an organism must keep earning to keep answering — it survives iff its per-cycle **surplus > 0** (MSC eq 19), and one whose every rule can fire nothing is dead by starvation. `epochs` returns the answer-count trajectory; `epochs-traced` returns (answers, surplus) per cycle. Runs in `&self` **or a worker's space**; each cycle **`set-cycle`** tags `(cycle-now k)` so `fire`/`fired?` scope to that cycle: the SINGLE event log accumulates cycle-tagged, in place — a rule re-fires each new cycle (`fire-once-per-cycle`) without the log ever being cleared. Re-hosted on the `ecan-epoch` worker — see `ecan.metta`. |
| `acs.metta` | the **ACS detector** (TECAN T3 / Alg 5.5 step 2 / MSC eq 18–19) — mine the reaction graph from the event log + rule IR, discover the food-generated reflexively-autocatalytic loop **A = (M_A, R_A)**, certify its §4.5 conditions, emit the §2.9 verdicts. Graph is keyed on the **MOTIF** — a rule's whole reactant/product PATTERN (a list of sem-edge clauses, jointly canonicalized so shared vars are kept — `rule-reactant`/`rule-product`/`canon-motif`), so a multi-edge premise like a causal chain is ONE composite motif; product-feeds-reactant is decided by **UNIFICATION** (`unify`/`motif-feeds?`, a common instance — handling subsumption, nested args, and a single edge feeding a multi-edge premise). **Structural closure** (§4.5 cond 1, `structurally-closed?`/`closure-kind`) is computed over the **endogenous** feeds ONLY — a member must both lie on a member-to-member feeds cycle (`rule-feeds-rule?`/`endo-cyclic?`) **and** have its whole non-food premise **injectively** regenerated by member products (`injective-covered?`: each non-food premise clause matched to a *distinct* member product; a clause no member produces is food and exempt). The injective half is what stops a *contracting* self-loop — two premise clauses of a relation, one product of it — from passing as a closed singleton, while a balanced singleton that regenerates its own catalyst still does. The evaluator's minting edge is **FOOD** (external reward), not closure. **Subset-mining**: `endo-component` peels the fired set to a fixpoint (dropping a feed-forward converter can un-cover a member that leaned on it), and `acs-member-set` takes that closed component when non-empty, else falls back to the food-fed candidate network (`acs-members`) so a not-closed candidate is still reported. The `acs-closure` fact is emitted **only when closed** (`closure-facts`), and `closure-kind` classifies it from the relations the loop **regenerates** (`closure-rels`, its members' non-food premise relations) against `(control-relation R)` declarations: `substrate` (all semantic) / `control` (all internally-generated control motifs) / `hybrid` (mixed). A **food-fed / subsidized candidate is NOT an ACS**, so it emits **no** `acs-closure` — its state is read off as surplus-but-no-closure (`closure-of` returns `none`). The food set is the cue motifs **and** the reward. Membership + closure are clamp-**independent**; the **clamp-switch shows in the componentwise `acs-surplus`** (`token-surplus`, eq 19) — a costed token whose income < spend fails condition 3 under that clamp (the same loop is viable under one clamp, starves under another). **Condition 4 (causal influence)** is a REPLAY ablation — `causal-influence?`/`ablated-answers` re-derive in a caller-bound **isolated** space with the members suppressed (`run-chamber-ablate`); if the answer count drops below the `total-answers` baseline, the loop causally produces the answers — computed ONCE as `$ci` and emitted as `acs-causal-influence`. **Per-rule causal coding** (SC §3) breaks that down per member: `member-do-influences` runs a **leave-one-out** replay per member and emits `rule-do-influence R target answer-reward cycles n` + `rule-redundancy R cycles bool`. The replay is a full **epoch** over a window of `cycles` (`windowed-reward` → `ablate-epochs` → `ablate-epoch`: re-derive with the rule suppressed → read the minted reward → **credit** it → `decay`), measured against an unablated run of the same length in a `wipe-space`d replay space. The crediting step is load-bearing: without income the organism cannot afford a second cycle, so ablated and unablated runs alike collapse to the first and every difference vanishes. The window is `window-of` = the observed log's cycle count **capped by `(acs-window-max n)`** (config, default 3; `window-max`) — pairing with the certified run on a short log, bounded on a long one, since past the cycle where the trajectories separate each further cycle only adds a constant — and it is recorded in the fact, because a rule whose product survives decay acts on the *next* cycle and so reads 0 over one cycle while being load-bearing over two. `minimal-acs` uses the same window and finds a working minimal set by **greedy sequential** ablation (`greedy-minimize` carries an accumulated skip set, so a *mutually* redundant group — each member droppable alone, not all together — keeps one survivor instead of collapsing to the empty set); it is *a* minimal set, not *the* minimum one. On a one-cycle window it would drop every self-priming loop's control rules and return a set that no longer closes, so the window is what makes it sound. `acs-verdicts` emits both **M_A** (`acs-motif` per motif species — `acs-motifs`, the cycle's motif patterns incl. the composite chain `((ReasonFor (mvar 0)(mvar 1)) (ReasonFor (mvar 1)(mvar 2)))`; food motifs excluded) and **R_A** (`acs-member`), plus `acs-closure` + `acs-autocatalytic` (structural, §4.5 cond 1–2), `acs-surplus` (cond 3), `acs-causal-influence` (cond 4) + `acs-recurrent` (recurrence over the cycle-tagged event log — one epoch = candidate); heritability (cond 5) is P3. Each condition is its OWN fact — there is **no `acs-promoted`/certified summary**; a consumer conjoins them ("certified ACS under CL" = `acs-closure` present ∧ every `acs-surplus`>0 ∧ causal ∧ recurrent). Reachability (`succs`/`preds`/`cycle-through`) is generic. Also carries `run-as`, the **acs-scan** worker body (the certification hosted as a §6.4 worker kind in isolated spaces). |
| `ctrl_scaffold.metta` | **CTRL-SCAFFOLD** — deriving a control level around a rule chain the log says keeps working. Detection is NOT done here: scaffolding is a second CONSUMER of the ACS scan, not a second scan. `acs-chain` (the members the scanner recorded) · `verdict-recurrent?` / `verdict-closed?` · **`scaffoldable?`** = recurs ∧ not closed — the trigger read off the scanner's own per-condition verdicts, in keeping with there being no single "promoted" summary fact. Plus `chain-answering-members` — the chain's DELIVERING end, computed from dataflow (a member whose own premise the chain feeds, producing what a query asks for) rather than read off an ordering, since the members are a connected set and the one ordering that exists (`rule-priority`) is the hack being removed. Then the **GENERATOR** `scaffold-facts`: a PURE function returning the wrapper's whole fact list — gated copies of each member (activation premise prepended, RHS untouched so product ids and achievement typing are unaffected) · `recall` (an arriving cue activates the strategy) · `worked` (premised on the delivering member's own RHS pattern, provenance id included, so a one-hop cannot claim a chain's success) · `learn` · `prime` (the closing edge) · the offspring organism with its own genome and dequote price · the control vocabulary it introduces. Purity is structural: `add-atom` does not evaluate, so a pre-built list plus one `add-all` is the only safe way to write facts with constructed compound ids. Fails closed on an undeclared cost or nothing delivered. Names no relation, question type or corpus item. |
| `worker.metta` | the shared worker **ENVELOPE** (MSC §6.4) — the worker-generic infrastructure every kind reuses (a *worker* is the general unit; context-chamber/reducer/… are *kinds*): `copy-molecules` (materialize the parser's **surface** molecules — never derived products, `mol-surface?` — into a worker's **isolated** hot-pool space, never `&self`, *"no shared-hot-pool mutation"*, so the worker re-derives from scratch), `restore-snapshot` (fuel from a declarative `(snapshot-fuel …)`), `worker-budget` (the deterministic `worker-budget-steps`), and `emit-summary` (firings + one `(worker-purse W O tok n)` per surviving purse → `&self`). The read-only IR stays in `&self`; only the compiled crules land there. |
| `chamber.metta` | the **context-chamber** worker body (`worker-kind context-chamber`) — `run-cc`: own space → `copy-molecules` → `restore-snapshot` → **`run-chamber-b`** (bounded by `worker-budget-steps`) → `emit-summary`. The derivation + the **cycle-tagged event log** live in the worker's space — the space-parameterized pipeline running off `&self` (via the `$ws`-threaded grounder + `clause-join`). Deriving only; minting (the ecan-epoch kind) is a separate body. |
| `ecan.metta` | the **ecan-epoch** worker body (`worker-kind ecan-epoch`) — the **minting** kind (vs context-chamber's deriving-only). `run-ee`: own space → restore snapshot fuel → run the **metabolic-closure epoch loop** (`epoch.metta`'s `epochs`, `mint+credit` each cycle) for `worker-cycles` cycles under `worker-clamp`, in isolation → emit the answer trajectory + total firings + final purse. The purse persists in the space across cycles; the single cycle-tagged event log accumulates in place. This is the epoch death re-hosted on a worker (the `[2,1,1]` starvation under `CL_shallow`). |
| `reducer.metta` | the **reducer** worker body (`worker-kind reducer`) — `run-reduce`: a **synchronization boundary** (MSC §6.4) that merges the per-worker summaries across a `par-group` into `(reduced total-firings PG n)` in `&self`. **Re-run-safe** — the reduced fact is replaced, not stacked (`clear-reduced`; the value is `let*`-bound before `remove-atom`). |
| `dispatch.metta` | the §6.4 worker **DISPATCHER** — `dispatch`: a `case` on `worker-kind` routing a worker to its body (`context-chamber`→`run-cc`, `ecan-epoch`→`run-ee`, `reducer`→`run-reduce`, `acs-scan`→`run-as`, `evaluator`→`run-eval`; an unknown kind hits the `$other` fallback). The switchboard only; the bodies live in their body modules. |

None of these logic modules carry data or a test of their own — each is a facts-free def collection that assumes the engine/evaluator is loaded by the consumer, and is exercised by the matching `*_test.metta` in `../tests/`. The end-to-end pipeline demo lives in `../experiments/expt1-causal-qa/demo.metta`.

## Why `&self` (not `&mork`)

`&mork`'s `match` (current MORK FFI) **cannot join**: a nested `&mork` match cross-products (the inner ignores the outer-bound var) and compound result-templates lose bindings. So derivation runs in `&self` (where nested `match` joins correctly), with each worker's mutable state in its own native `(new-space)`. MORK-accelerated conjunctive matching needs a `query-multi` FFI primitive (deferred). Other PeTTa idioms in play: `case`-over-`collapse` = fire-once dedup + negation; runtime var-minting in the converter; `&self` doesn't dedup so the engine uses set-semantics add; a failing `!(test)` aborts the file.

**Refinement (`../tests/spaces_behavior_test.metta`):** the no-join limitation is specific to the `&mork` FFI — *native* fresh `(new-space)`s join under nested match exactly like `&self`, and even join *across* spaces. That cross-space join is what lets the worker ecology keep the read-only IR shared in `&self` while each worker holds its mutable state in its own space.
