# `tests/` — the Mortal Semantic Chemistry suite

Each `*_test.metta` file loads the engine modules it exercises (+ the Exp-1 data where needed), wires a scenario, and runs its own `!(test …)` assertions — so it **both demonstrates** a slice of the stack **and verifies** it. The *generic* logic lives in `../petta/`; the test file is thin (import + scenario + asserts). A failing `!(test)` prints `is X, should Y. ❌` and halts that file (`../../PeTTa/src/metta.pl`). The reference for correctness is **Ben's `docs/` PDFs**.

## Run

```sh
sh tests/run_suite.sh              # from the repo root (or anywhere in the repo)
```

Runs every `tests/*.metta` from the repo root (imports are repo-root-relative), tallies ✅/❌ per file, and exits non-zero on any failure. **Suite: 389 tests green.** One file at a time:

```sh
sh ../PeTTa/run.sh tests/grounder_test.metta < /dev/null 2>&1 | grep should
```

## The tests

- ✅ **solve pipeline** (`grounder_test.metta`, 18; logic `petta/grounder` + the engine) — the Exp-1 pipeline on the **§10.1 sem-graph IR** (V3): the parser's surface molecules carry discourse cues only; the **derivation genome** (`rules.metta`: `R_so`/`R_result` normalize cues → `ReasonFor`, `R_trans` chains **derived** edges) fires fuel-gated on the organisms' purses (3 firings — O_base's R_so/R_result @ sm, O_chain's R_trans @ sm + tr); then the parser's *why*-skeleton grounds against the derived graph **2 ways** (proximate + root cause, cited by provenance-bearing ids `(norm E)`/`(trans E1 E2)`; the mechanism chain is carried by the root cite's trans-id provenance, never by the query's shape).
- ✅ **evaluator** (`evaluator_test.metta`, 25; logic `petta/evaluator`) — **achievement-typed minting** on the solve pipeline: Match binary per grounding (every solution mints); achievements detected structurally (`skeleton-match` always; `transitive-explanation` when the cited derivation is a chain, depth ≥ 2 off the provenance ids) and converted to typed fuel by `(clamp-mint …)` facts — the **TYPED clamp-switch**: sm income equal under both clamps (8 = 8), **tr income 0 (`CL_shallow`) vs 2 (`CL_deep`)**, so only the deep clamp replenishes what `R_trans` spends; **provenance-based crediting** routes each grounding to the organism whose rule derived its cited edge (proximate → `R_result` → `O_base`; root → `R_trans` → `O_chain`).
- ✅ **working a task** (`epoch_test.metta`, 24; logic `petta/epoch`) — a task arrives, its text lands in a **fresh hot pool** (`refresh-pool`), and the chamber runs cycles until it **settles** (a whole cycle fires nothing). Products persist across the cycles of ONE task — a chain needs its intermediates alive when the cycle that consumes them runs — and a rule whose products are already present does not re-fire, so a settled task stops spending (cycle 2 costs nothing). What crosses a task boundary is what MSC eq 8 puts in the organism: the purse `F` and the log `L` ride with the soma while the hot pool `X` turns over — the test pins that the retired task's TEXT is gone from the pool while its firings remain in the log. Then the **task stream**: under `CL_shallow` `O_chain` earns no `tr`, so by the second arrival it cannot chain and only the proximate answer survives (`2 → 1`); under `CL_deep` the chain funds itself and all three arrivals get both answers, `tr` growing +1 each. Spend is now per task rather than per text ever seen, so `O_base` earns the same 4 and spends the same 2 on every arrival, however many texts it has already seen.
- ✅ **expression costs fuel** (`expression_test.metta`, 33; logic `petta/compiler`+`fuel`) — dequoting a genome into a **soma** costs (MSC eq 20 `cexpr`), while compiling a quoted rule stays free as a shared build artifact. Charged **once per hot pool**, not per cycle — eq 20 keeps `cmaint` (being alive) apart from `cexpr` (the act of dequoting), and a per-cycle charge would be rent under the wrong name. The sharp consequence is a death mode **prior to** starvation-by-firing: an organism holding 100 `sm` and no `dq` has no soma and runs **nothing**, spending nothing trying; give it one `dq` and the same genome comes alive unchanged. A partial case pins the granularity — `O_base` affords a soma and normalizes the cues while `O_chain` does not, so the chained answer never appears despite ample `sm`+`tr`. The soma outlives `refresh-pool` (X turns over, the expression does not) and is cleared by `reset-run`. Expression is **never free by omission** — a genome with no declared cost, or an organism with no genome, is refused however rich its purse, so a forgotten declaration surfaces as an organism that does not run rather than one that runs unpriced. Also pins that a purse holds **zero**, not "empty", of a token it has no fact for — otherwise `afford?` cannot decide on a token never held.
- ✅ **ACS detection** (`acs_test.metta`, 94; logic `petta/acs`) — the P2 mortal-ACS certification (TECAN T3 / Alg 5.5 step 2 / MSC eq 18–19) on one chamber run. The reaction graph is keyed on the **motif** — a rule's whole reactant/product PATTERN (composite, shared vars kept; `rule-reactant`/`rule-product`), matched producer→reactant by **unification** (`motif-feeds?`), so R_trans reads as autocatalytic (its single `ReasonFor` product feeds its two-edge chain premise) and R_so/R_result as food-consumers (the `So`/`AsAResult` motifs are never produced = food). The **food-generated loop** = `{R_so, R_result, R_trans}` (all in the food-fed reaction network). **Structural closure** (§4.5 cond 1, endogenous feeds only): `R_so`/`R_result` are feed-forward cue-converters (the minting edge is FOOD, not closure), and while `R_trans` is endo-cyclic its two-`ReasonFor` premise is not **injectively** covered once the converters peel away, so the closed component is **empty**, the member set falls back to the food-fed candidate, and the set emits **no `acs-closure` fact** (a subsidized candidate, inferred as surplus-but-no-closure). Synthetic rings validate the closed branches and the **closure-kind** classifier: an all-semantic `P→Q→P` ring reads `substrate`, a control⇌semantic ring `hybrid`, a control⇌control ring `control`. **Componentwise surplus** (eq 19): `sm +1` under both clamps, `tr +1` (`CL_deep`) vs `tr −1` (`CL_shallow`) — so the **`acs-surplus` `tr` component flips** `+1`/`−1` while membership + closure stay fixed. **Condition 4 (causal influence)** is a **replay ablation** — suppressing the members in a caller-bound isolated space (`run-chamber-ablate`, fuel from `SNAP_qa`) drops the answers `2 → 0`; the negative control (suppress nothing) holds at `2`, so the assay is a real counterfactual. Emits the §2.9 verdicts as the full **A = (M_A, R_A)**: `acs-member` (R_A rules) + `acs-motif` (M_A = the cycle's motif patterns — the single ReasonFor motif AND the composite chain motif; food motifs excluded) + `acs-autocatalytic` (§4.5 cond 2) alongside `acs-closure`/`acs-surplus`/`acs-causal-influence` (cond 4, computed once)/`acs-recurrent` (there is **no `acs-promoted` summary** — the per-condition verdicts are conjoined by a consumer). Finally the **acs-scan worker** (`dispatch` → `run-as`) runs the same certification in **isolated** spaces — it **consumes** the log a prior chamber run leaves in its run space (2 answers, 3 firings), builds the graph + replays the ablation in its own graph/ablation spaces, emits the verdicts to `&self`, and a second worker under `CL_shallow` flips the `tr` surplus sign — the clamp-switch through the worker layer. Finally **recurrence** (§4.5 "sustains itself in an event log"), counted across **tasks** rather than cycles — the docs' metric is "recurrence of useful motifs across tasks", so a loop recurs when it turns again on newly arrived material, not when one question is re-asked: one arrival leaves `acs-recurrent` `False` (a structural candidate), a second task on which the same loop turns flips it `True` (`recurrence-count`/`loop-in-task?`), and a loop that turned for only one of the two does not count. Surplus is scoped the same way (`rule-firings` counts the posed task's cycles, eq-19), so a multi-task log keeps surplus per task. Then **per-rule causal coding** (SC §3): the leave-one-out `member-do-influences` measure all three V3 members load-bearing in minted reward (`R_result 6` — it makes the edge both answers need; `R_so`/`R_trans` `4` each, the chain answer), so the minimal ACS is all three. Finally **mutual redundancy** — two synthetic rules deriving the *identical* product edge, so either alone reproduces the answer but dropping both loses it: each measures do-influence `0` (a correct per-rule reading), and `minimal-acs`'s greedy sequential ablation keeps one instead of returning the empty set. A closing block pins the replay **window**: it is the task sequence the observed log served, capped by `(acs-window-max n)` (default 3, config-overridable), so a one-task log is not padded up and a five-task synthetic log is truncated to 3 — bounding what a production log costs, and bounding what a `0` claims.
- ✅ **the firing engine** (`reaction_test.metta`, 28; logic `petta/reaction`) — **TECAN Alg 5.1 collect-then-fire**. The candidate queue is assembled against the **epoch-start state** before anything fires, so on V3 `R_trans` — which has no `ReasonFor` edge to chain yet — is simply not in cycle 1's queue: the chain advances **one hop per cycle** and the answer count climbs `1 → 2` as it goes. That makes one chamber run **one epoch, not a finished derivation**; a caller that wants the whole chain runs epochs until one fires nothing, which is `work-task` with the metabolic bookkeeping and `settle-from` as the bare assay. The **task absorbs the retiming**: because a task runs until its chamber settles it just takes a third cycle, and the answers, purses and cycle-numbering of a three-arrival stream are what the whole derivation always cost. Then the pieces of Alg 5.1 itself — the epoch bound `B` stops the queue being popped mid-way (line 12); an entry whose **re-check** fails is **dropped** and the queue continues (line 14), so `O_base`'s affordable work still fires behind an entry that exhausted `O_chain`'s last `tr`; and the settle guard holds at fire time too, so two producers of the same product can both be collected and the second pays nothing.
- ✅ **ctrl-scaffold: reading the scan** (`ctrl_scaffold_test.metta`, 101; logic `petta/ctrl_scaffold`) — step 1 of deriving a control level, which turns out to need **no detection of its own**: the ACS scanner already reads the task-dated log, and `scaffoldable?` just conjoins its per-condition verdicts — RECURS across arrivals (a track record justifies the expense) ∧ does NOT close (so there is something for a control level to supply). The two clamps make the discrimination: under `CL_deep` the chainer is funded, the same three rules work both arrivals, and the candidate is scaffoldable; under `CL_shallow` it starves on the second arrival and the **same three rules with the same structure** fail the trigger on their record alone. A closed candidate needs no wrapper however well it recurs, and an unknown one triggers nothing — absence is not a licence. The delivering end is then computed from dataflow — `R_trans`'s premise is member-fed, `R_so`'s is a food cue — since the members are a connected set with no unique first, and the ordering that does exist is the one being removed. **Step 2, the generator:** `scaffold-facts` is pure (50 facts built, nothing stored) and deterministic, and fails closed on an undeclared rule cost or a chain that delivers nothing. A gated copy keeps its RHS verbatim, so product ids and achievement typing are untouched. **The success trace is strict, and the test shows why it has to be computed rather than matched:** at the motif level a one-hop and a chained product are the *identical* motif, so no motif could separate them — the trace therefore premises on the delivering member's own RHS pattern, `(trans …)` id included, which only a completed chain mints. The rest pins the ring (`recall` in, `worked` → `prime` closing it, with `recall` and `prime` minting different ids so both can fire), the offspring organism with its own genome and dequote price, and the control vocabulary that makes the closure classify as control-level. **Step 3, the worker:** the parents are the organisms that contributed the chain, and each owes per member it gave — `O_base` 2:1 over `O_chain`, exactly their contributions. The endowment moves out of the parents' purses and into the offspring's, leaving it able to express itself (an offspring that could not would be stillborn). And the point of billing parents at all: **a parent too poor to endow cannot reproduce** — the run returns `unaffordable` and the *solvent* co-parent is not charged for a wrapper that never gets built. A candidate with no track record is refused earlier still, as `not-scaffoldable`. **Step 4, the deliverable:** the offspring runs a stream of arrivals in its OWN chamber (`scaffold-qa` admits the generated rules and not the originals they copied, so a gated rule and its original never race for the same product id), pays to express itself out of the endowment, answers both arrivals, and stays solvent. The ring turns for the reason the wrapper exists — the arriving cue lets `recall` ignite a cold pool, and once the chain has delivered it is `prime`, fed by the success trace that delivery laid down, that re-activates it. Then the SAME detector, unchanged, certifies the generated set: `recall` peels out as food intake, the remaining five are **structurally closed at the HYBRID level** (regenerating Primed/Worked *and* ReasonFor), autocatalytic, causally load-bearing (suppress the ring and the arrival goes unanswered), and **recurrent across both arrivals**. Closing the loop: the wrapped set is no longer `scaffoldable?` — it now closes, which the chain it was made from never did.
- ✅ **worker isolation + the evaluator worker** (`worker_test.metta`, 16; logic `petta/chamber`+`worker`+`evaluator`) — the context-chamber worker (MSC §6.4) runs the V3 pipeline in its **own hot-pool space**, not `&self`. The runner binds the space; `run-cc` materializes the molecules into it (`copy-molecules`), restores fuel from `(snapshot-fuel …)`, and runs the chamber there. **Isolation**: after the run, `&self` has *no* derived edges and *no* event log (the molecule cue untouched); the worker's space holds the 3 `ReasonFor` edges, the 3-firing **append-only** log, and the spent purses. Grounding against the worker's space answers the question (2 ways) — the space-parameterized grounder + `clause-join` running off `&self`. `emit-summary` writes `worker-firings` + `worker-purse` to `&self`. Then an **evaluator worker** (`run-eval`, worker-kind `evaluator`) mints on that **same** derived space — the minting stage `run-cc` omits, a sequential pipeline handoff — under `CL_deep`: `O_chain` earns back the `tr` the chamber spent to 0 (+ `sm`), `O_base` earns `sm`, each grounding credited to the organism that derived it; the resulting purses are emitted to `&self` as the token delta.
- ✅ **multi-worker orchestration** (`multiworker_test.metta`, 9; logic `petta/worker`+`reducer`+`dispatch`) — the §6.4 P4 layer. Two context-chamber workers over `CH_expt1` in **separate** spaces: `W_full` unbounded (3 firings, 2 answers); `W_lean` with `(worker-budget-steps W_lean 2)` **halts after `R_so`+`R_result`** (no `R_trans` → 1 answer). **Isolation**: `W_full` spends its `tr`, `W_lean` never reaches `R_trans` so its `tr` is untouched — neither touches the other. `dispatch` routes each by `worker-kind`; the **reducer** merges the two summaries into `(reduced total-firings PG_qa 5)`, and dispatching it again stays 5 (**re-run-safe**).
- ✅ **ecan-epoch worker** (`ecan_test.metta`, 10; logic `petta/ecan`+`epoch`+`worker`) — the MINTING worker kind (as against context-chamber, which only derives), working ONE arriving task in an isolated space. `dispatch` routes `ecan-epoch → run-ee`, which poses the worker's task, opens a fresh hot pool with that task's text, runs cycles until the chamber settles or `worker-cycles` runs out, then mints under `worker-clamp`. The task is answered both ways; the seeded `tr` covers its one chaining and `CL_shallow` mints none back, so a next arrival would go unchained. Cycle 1 does the work and cycle 2 finds every product present and fires nothing — which is what ends the task; both cycles are dated to it. A worker is handed one task; a stream of them is the harness's business, not the worker's. Isolation: `&self` has no derived edges.
- ✅ **context gate** (`context_gate_test.metta`, 6) — the generic **chamber-scoped `rule-context` gate** (`petta/gate`: `rule-eligible-in?`). Two synthetic rules with identical LHS but different context — one a `chamber-context` of `CH_expt1` (admitted by `run-chamber`, fires once per `qa-question`), one not (rejected, never fires) — exercise **both** branches of the gate.
- ✅ **per-organism fuel + attention gate** (`tecan_shell_test.metta`, 14; logic `petta/fuel`+`petta/gate`) — the per-organism fuel ledger, attention state, and computed gate. Synthetic organisms/rules exercise (1) **`rule-organism`** resolution via ruleset membership (two organisms resolve distinctly), (2) the **per-organism purse** — `afford?`/`debit` hit the firing organism's own `(fuel O tok n)`, two organisms in one space stay **isolated**, and (3) the **per-firing gate** `gate?` = `afford?` ∧ `in-attn?` (context settles at chamber admission), hitting the afford-fail and attention-below-threshold (cold-rule) **reject branches**.
- ✅ **spaces battle-test** (`spaces_behavior_test.metta`, 11) — the regression guard proving fresh `(new-space)`s join under nested match (unlike `&mork`), join *across* spaces, and that handles are storable in facts; the basis for the worker-isolation choice.
